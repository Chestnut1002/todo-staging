## 缺陷 #1：拖拽排序后刷新页面顺序还原

| 属性 | 内容 |
|------|------|
| **缺陷ID** | BUG-001 |
| **严重程度** | 🔴 中等 — 功能核心逻辑失效，但不会导致崩溃 |
| **优先级** | P1 — 影响用户体验，需在下个版本修复 |
| **发现版本** | v2.0 |
| **发现日期** | 2026-06-10 |
| **所属模块** | 拖拽排序 |
| **报告人** | [你的名字] |

### 复现步骤

1. 已有任务 A、B、C 三个（按此顺序）
2. 鼠标拖拽任务 C 到任务 A 前面
3. 观察列表顺序 → 变为 C、A、B（符合预期）
4. 按 F5 刷新页面
5. 观察列表顺序 → 恢复为 A、B、C

**复现率：** 100%（每次必现）

### 预期结果

拖拽排序后应调 `Storage.saveAll()` 将新顺序持久化到 localStorage，刷新页面后顺序保持不变。

### 实际结果

拖拽操作仅更新了 DOM 的显示顺序，未同步写入 localStorage。刷新后从 localStorage 读取的仍是旧顺序。

### 根因分析

拖拽结束（`dragend`）的回调函数中只执行了 `render()` 更新视图，缺少 `Storage.saveAll()` 调用。将排序后的 `tasks` 数组回写存储即可修复。

### 影响范围

- 影响：拖拽排序功能无法持久化
- 不影响：添加、删除、搜索等其他模块

### 修复方案

在拖拽结束回调中增加一行 `Storage.saveAll(reorderedTasks)`。

### 回归测试

| 用例 | 结果 |
|------|------|
| 拖拽后刷新 — 顺序保持 | ✅ 通过 |
| 拖拽后再添加新任务 — 新任务在末尾 | ✅ 通过 |
| 拖拽后再删除任务 — 正常删除 | ✅ 通过 |
| 拖拽后再切换视图 — 顺序保持 | ✅ 通过 |

### 状态

✅ 已关闭 — 2026-06-10

## 缺陷 #2：搜索时视图切换按钮未隐藏

| 属性 | 内容 |
|------|------|
| **缺陷ID** | BUG-002 |
| **严重程度** | 🟡 轻微 — 不影响功能，但逻辑不一致 |
| **优先级** | P2 — 体验优化 |
| **发现版本** | v2.0 |
| **发现日期** | 2026-06-10 |
| **所属模块** | 搜索 |
| **报告人** | [你的名字] |

### 复现步骤

1. 在搜索框输入关键词进入搜索模式
2. 观察顶部栏 — 导航按钮（◀ ▶ 今天）已隐藏，但视图切换标签（日/周/月）仍可见
3. 在搜索模式下点击"周"标签

**复现率：** 100%

### 预期结果

搜索模式下应隐藏所有导航和视图切换元素，或点击视图切换自动退出搜索。

### 实际结果

视图切换标签在搜索模式下仍可点击，切换到其他视图后搜索结果未更新且界面状态混乱。

### 根因分析

搜索模式进入时只隐藏了 `#navPrev`、`#navNext`、`#todayBtn`，未处理 `.view-tabs` 的显隐逻辑。

### 影响范围

- 仅搜索模式下的 UI 一致性问题

### 修复方案

在进入搜索模式时同时隐藏视图切换标签；退出搜索时恢复。

### 回归测试

| 用例 | 结果 |
|------|------|
| 搜索后视图标签隐藏 | ✅ 通过 |
| 退出搜索后视图标签恢复 | ✅ 通过 |
| ESC 退出搜索后视图正常切换 | ✅ 通过 |

## 缺陷 #3：空任务名可添加（缺少前端校验）

| 属性 | 内容 |
|------|------|
| **缺陷ID** | BUG-003 |
| **严重程度** | 🟡 轻微 — 不阻塞流程，但产生无效数据 |
| **优先级** | P2 |
| **发现版本** | v1.0 |
| **发现日期** | 2026-06-09 |
| **所属模块** | 任务添加 |
| **报告人** | [你的名字] |

### 复现步骤

1. 输入框不输入任何内容
2. 点击 + 按钮或按 Enter

**复现率：** 100%

### 预期结果

前端拦截空输入，阻止提交并在输入框下方显示提示"任务名不能为空"。

### 实际结果

无任何反应，用户点击操作后无反馈，可能误以为按钮卡住了。

### 根因分析

`TaskList.add()` 方法中未校验 `title.trim() === ''` 的场景，也未给出用户反馈。

### 影响范围

- 仅添加操作的用户体验

### 修复方案

在 `add()` 方法开头增加空值校验：
```js
if (!title.trim()) {
  input.placeholder = '请输入任务内容';
  return;
}
```

### 回归测试

| 用例 | 结果 |
|------|------|
| 空输入点击 + — 提示错误 | ✅ 通过 |
| 空输入按 Enter — 提示错误 | ✅ 通过 |
| 正常输入添加 — 不受影响 | ✅ 通过 |

### 状态

🟡 待修复
